# src共通処理のリファクタリング

対象：2026-09-07、基点コミット `2774c2d`。

## 目的

複数領域にコピーされている処理を、その責務を持つモジュールへ集約する。
既存の分析結果と呼び出し方を維持し、修正箇所の分散と領域をまたぐ不要な依存を減らす。

## 設計

| 対象 | 配置・変更 | 維持する契約 |
| --- | --- | --- |
| 賃金・労働時間・出勤日数の月次抽出 | `monthly_labor_service.py` に共通抽出関数を追加。既存の3サービスは条件と列名を渡す | 公開関数の引数・既定値、列順・型、CY除外、数値変換、欠損除外、重複年月の末尾採用、エラー文言 |
| CPI・名目賃金・実質賃金の変化率 | `time_series.py` に計算を集約 | 日付順ソート、前行・12行前との比較、欠損の非補完、出力列名。実質賃金固有の必須列検証も維持 |
| 年平均CPI | `minimum_wage_analysis.py` から `cpi_analysis.py` へ移動 | 期間の既定値、12件の非欠損観測の確認、出力。旧importも互換ラッパーで維持 |
| e-Stat通信 | `estat_client.py` 内の非公開関数へGET・JSON解析・APIステータス確認を集約 | リクエストパラメータ、タイムアウト、戻り値、例外型・文言・原因 |
| e-Statの単一値／リスト処理 | `estat_response.py` に `ensure_list` を集約 | `None`・リスト・単一値の扱い。既存サービスからのimportも維持 |

汎用のクラス階層や全領域共通のDataFrameスキーマは導入しない。
各公開関数は領域固有の既定条件・名称・検証を保持する。
新規コードと確認スクリプトは正本モジュールを直接参照し、既存import経路は互換性のために残す。

## 今回変更しない分析仕様

- CPIの基準改定・統計表ID、調査方法変更への対応。
- 年平均の定義、最低賃金の年度・暦年対応、相関の計算方法。
- 月の欠落・重複時の変化率仕様や、年平均CPIの暦月完全性判定。
- 分析用の分類コード、基準年、公開画面。

これらは結果に影響する仕様変更として個別に設計・検証する。

## 検証と完了条件

1. 変更前の既存テスト・静的チェック結果を記録する。
2. 共通化で失われやすい入力条件（空白、CY、非数値、重複月、欠損値）を公開関数から確認する。
3. e-Stat通信の正常系・接続失敗・JSON失敗・APIエラーをモックで確認する。
4. 既存入力ファイルを用いるテストを含め、全テストを再実行する。
5. 変更ファイルのRuffチェック・整形と差分レビューを行う。
6. 変更を独立したブランチとドラフトPRにまとめる。

分析完了や統計的妥当性を、このリファクタリングの成功だけから判断しない。
